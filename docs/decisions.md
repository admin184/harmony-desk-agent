# 决策记录

## D1：第一期只做单人自用工具

日期：2026-10-03

**结论：** 目标用户是我自己，不考虑多用户、租户、团队协作和公开商业化。

**原因：** 先验证真实工作流，避免被账号体系、权限体系和合规成本拖慢。

## D2：第一期任务范围限定为文件 / 数据类 + 开发 / 系统类

日期：2026-10-03

**结论：**

- 做：文件整理、数据处理、脚本编写、命令执行、开发环境维护。
- 二期：跨设备流转。
- 暂缓：模拟鼠标键盘操控 GUI 软件。

**原因：** 命令行和脚本路线可以建立清晰安全边界，开发速度和可靠性更好。

## D3：手机端必须是独立 App

日期：2026-10-03

**结论：** 不接受手机浏览器作为主要入口，要做成独立鸿蒙 App。

**原因：** 用户明确认为浏览器不好用，且独立 App 能提供更稳定的入口、通知和会话体验。

## D4：优先调研和复用现有开源项目的架构经验

日期：2026-10-03

**结论：** 在自研前研究 Happier、Omnara、Open Interpreter 等项目，优先复用成熟架构思路。

**原因：** 这个需求已有相近开源实现，不应从零猜测通信、会话持久化、权限确认和 Agent 执行设计。

## D5：项目定名为 Harmony Desk Agent

日期：2026-10-03

**结论：**

- 展示名：Harmony Desk Agent
- GitHub 仓库名：`harmony-desk-agent`
- 本地项目目录：`harmony-desk-agent`

**原因：**

1. 名称直接表达“鸿蒙手机端 + 桌面电脑 Agent”的核心结构；
2. 使用英文短横线命名，适合作为 GitHub 仓库名；
3. 当前搜索未发现同名项目，重名风险较低；
4. 不把 Windows、AI、远程控制等词全部塞进名称，避免名字过长。
